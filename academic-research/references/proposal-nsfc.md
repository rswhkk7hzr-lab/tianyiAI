## 1. 申报书结构与撰写总原则

**正文核心章节**（面上/青年/地区项目通用）：
1. 立项依据（研究意义 + 国内外研究现状述评 + 参考文献）
2. 项目的研究内容、研究目标，以及拟解决的关键科学问题
3. 拟采取的研究方案及可行性分析（含技术路线）
4. 本项目的特色与创新之处
5. 年度研究计划及预期研究结果
6. 研究基础与工作条件

**总原则**：
- 核心是凝练**科学问题**（认识自然、揭示规律的问题），不是工程实现或产品开发问题
- 全文围绕一条主线：科学问题 → 研究内容 → 研究方案 → 预期成果，环环对应
- 假说驱动：明确"提出什么假说、如何验证"
- 评审人视角写作：3-5 分钟快速浏览，各级标题即论点，让标题自己会说话
- 依托用户真实研究方向与前期成果撰写；研究基础不足时如实告知风险，不虚构成果

## 2. 立项依据撰写

**结构模板**（通常 3-8 页）：
```
2.1 项目的立项依据（研究意义、国内外现状、主要参考文献）
（1）研究意义：应用场景中的重大需求 → 现有手段的瓶颈 → 瓶颈背后的科学挑战
（2）国内外研究现状：按 3-4 条脉络综述（时间/主题组织）→ 每条脉络结尾评述 →
    归纳"三个仍然"（仍未解决…/仍不清楚…/仍缺乏…）
（3）本项目切入点：针对上述缺口，提出科学假说/核心思路
（4）参考文献：30-60 条，近 5 年过半，含国际高水平文献与国内同行工作
```

**写作要点**：
- 现状述评是"漏斗式"：从大领域快速收缩到具体科学问题，背景不超过 1 页
- 评述要指出已有工作"做不到什么、为什么做不到"，为本研究"为什么能"铺垫
- 每个论断尽量有文献支撑；综述写法遵循 literature-review.md
- 参考文献格式遵循 citation-gbt7714.md；禁止编造文献

## 3. 研究内容、目标与关键科学问题

**研究内容**（3-4 条为宜）：
- 每条一个相对独立又递进的模块，句式"研究内容X：XXX的XXX机制/方法研究"
- 内容量与资助强度匹配（青年 3 条左右，面上 3-4 条），贪多必被批"不聚焦"
- 内容之间逻辑：基础机理 → 方法构建 → 验证应用，层层递进

**研究目标**（1 段或 3 条内）：
- 与研究内容一一呼应，可检验、可实现（5 年内）
- 句式"揭示…机制/建立…方法/研制…系统/形成…理论"，避免"达到国际领先"类空话

**拟解决的关键科学问题**（1-2 个，最多 3 个）：
- 是"科学层面"的问题：为什么/机制是什么/规律如何
- 每个问题 + 一句话说明为什么关键（不解决则项目目标无法实现）
- 反例（不合格）：如何实现 XX 系统的开发（这是技术问题）

## 4. 研究方案及可行性分析

**结构模板**：
```
4.1 总体研究思路与技术路线
（1）总体思路：一段话 + 一张技术路线图（必画）
（2）技术路线图：科学问题 → 研究内容 → 方法手段 → 预期成果 的流程图，
    体现各内容间的数据/逻辑衔接；用绘图能力生成
（3）科学假说图/机制图（假说明确时必画）：暴露 → 机制路径 → 结局，
    内容规范见下方小节，视觉规范见 data-visualization.md 第 6 节
4.2 具体研究方案
按研究内容逐条展开：采用什么数据/材料 → 什么方法步骤 → 输出什么 → 衔接下一条
（关键步骤给参数、判据，体现"想清楚了"）
4.3 可行性分析
（1）理论可行：思路有文献/理论依据
（2）技术可行：关键方法有已发表先例或前期验证
（3）条件可行：已有设备、数据、合作基础
4.4 风险分析与应对（加分项）：Plan B 设计
```

**要点**：
- 方案颗粒度：让同行评审判断"此人已经想清楚怎么做"，而非复述教科书方法
- 技术路线图是评审重点，单独一页、要素完整、逻辑闭环

### 科学假说图/机制图（内容规范）

机制图回答"为什么会发生"（因果路径与理论逻辑），与技术路线图（回答"怎么做"）配套使用、不合并。申报书标准配置：立项依据末尾提假说处或研究方案开头放一张假说图，研究方案 4.1 放一张技术路线图。

- **要素**：暴露/干预节点 → 中介路径 → 结局节点；调节变量从侧方入箭；每条路径标注效应方向（+/−）与假设编号（H1、H2…）
- **图文对照**：图上每条路径必须能在假说文字中找到对应句；变量命名与全文术语一致（不做同义改写）
- **路径证据分层**：已有文献支撑的路径与本研究新提出的假说路径区分标注（如实线/虚线，规范见 data-visualization.md 第 6 节）
- **与验证环节挂钩**：每条主要路径应在技术路线图中对应验证步骤，形成"假说 → 验证 → 结论"闭环
- **常见错误**：箭头语义不明（未区分促进/抑制）、图与假说文字脱节、核心节点过载（>7±2 个）、把机制图画成技术路线图（混入步骤/流程内容）

## 5. 特色与创新之处

- 2-3 条，分类陈述：理论创新（新机理/新模型）/ 方法创新（新方法/新范式）/ 应用创新（新场景/新数据）
- 每条结构："区别于已有…（对比对象），本项目首次/通过…（做法），实现…（突破点）"
- 忌自我拔高（"国际首次"须确有依据）、忌把研究内容换个说法当创新

## 6. 研究基础与工作条件

- **前期基础**：与本项目直接相关的已发表论文、预实验数据、已建立的方法体系（列证据，可放代表性图表）
- **工作条件**：实验室平台、设备、数据资源、团队构成（按申报书实际栏目填写）
- 青年项目另注意：个人简介突出独立性，说明与博士课题的关系（延续中深化，非简单重复）
- 只陈述真实成果，由用户提供材料，不代拟虚构

## 7. 常见毙稿原因（自查清单）

- [ ] 科学问题不凝练或其实是技术/工程问题
- [ ] 研究内容过多、彼此缺乏内在逻辑
- [ ] 创新点空泛，无对比依据
- [ ] 技术路线与研究内容脱节（有内容无对应方法）
- [ ] 立项依据综述罗列文献、无批判性评述、无研究缺口论证
- [ ] 研究基础与项目方向不相关
- [ ] 关键方法交代含糊，被疑"没想清楚"
- [ ] 参考文献陈旧（近 5 年占比低）或有编造嫌疑
- [ ] 摘要（400 字中英文）与正文主线不一致

## 8. 撰写工作流程

1. **信息收集**（必需）：用户的研究方向、目标学部/学科代码、项目类型（面上/青年/地区）、前期成果清单、可用的数据与条件。缺项先询问。
2. **提纲确认**：先输出全文提纲 + 技术路线草图文字稿，经用户确认再展开。
3. **分章撰写**：按上述模板逐章撰写，每章完成后交用户核对事实性内容。
4. **汇总润色**：全文一致性检查（题目-摘要-内容-目标-成果一条线），语言润色按 paper-polish.md。
5. **交付**：`.docx` 格式（可用 docx skill），技术路线图单独交付图片文件。

**其他类型申报书**：省部级项目、社科基金等结构相近（立项依据/研究内容/方案/基础），核心方法论通用；具体栏目按对应申报书模板调整。
