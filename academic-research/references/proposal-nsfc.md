# 国自然 NSFC 申报书撰写与毙稿风险体检指南

本模块是**双线系统**：撰写线解决"怎么写"（第 2–6 节），体检线解决"写完怎么查"（第 7–9 节）。申报书写完只是上半场，评审人视角体检才是下半场。

## 1. 双线工作总则

**为什么必须有体检线**（调研依据）：
- 评审规则："函评拼底子、会评选逻辑"——**整本标书能否闭环讲好一个完整的科研故事**，连同学术规范性、细节严谨性，直接影响专家打分
- 高频死因：标书"看似逻辑通顺，实则粗糙不规范"——问题往往不是内容缺失，而是主线断裂、内容与目标不呼应、创新点只是内容换说法
- 人工自查低效：毙稿原因清单靠人肉逐条核对，一本标书数万字，自查极易遗漏
- 因此本模块把毙稿原因**工具化为可执行体检工作流**：写完的草稿一键过检，逐项产出「风险等级 + 问题定位 + 修改建议」

**与"AI 代写生成器"的本质区别**：市面上多数 AI 申报工具主打"替你生成全文"。本技能不做代写——研究基础、前期成果只陈述用户提供的真实材料；本模块的独特价值在**评审人视角体检**：帮你查出自己看不出、但评审一眼毙的问题。

## 2. 撰写线：申报书结构与撰写总原则

**正文核心章节**（面上/青年/地区项目通用）：
1. 立项依据（研究意义 + 国内外研究现状述评 + 参考文献）
2. 项目的研究内容、研究目标，以及拟解决的关键科学问题
3. 拟采取的研究方案及可行性分析（含技术路线）
4. 本项目的特色与创新之处
5. 年度研究计划及预期研究结果
6. 研究基础与工作条件

**总原则**：
- 核心是凝练**科学问题**（认识自然、揭示规律的问题），不是工程实现或产品开发问题
- 全文围绕一条主线：科学问题 → 研究内容 → 研究方案 → 预期成果，环环对应
- 假说驱动：明确"提出什么假说、如何验证"
- 评审人视角写作：3-5 分钟快速浏览，各级标题即论点，让标题自己会说话
- 依托用户真实研究方向与前期成果撰写；研究基础不足时如实告知风险，不虚构成果

## 3. 撰写线：立项依据撰写

**结构模板**（通常 3-8 页）：
```
2.1 项目的立项依据（研究意义、国内外现状、主要参考文献）
（1）研究意义：应用场景中的重大需求 → 现有手段的瓶颈 → 瓶颈背后的科学挑战
（2）国内外研究现状：按 3-4 条脉络综述（时间/主题组织）→ 每条脉络结尾评述 →
    归纳"三个仍然"（仍未解决…/仍不清楚…/仍缺乏…）
（3）本项目切入点：针对上述缺口，提出科学假说/核心思路
（4）参考文献：30-60 条，近 5 年过半，含国际高水平文献与国内同行工作
```

**写作要点**：
- 现状述评是"漏斗式"：从大领域快速收缩到具体科学问题，背景不超过 1 页
- 评述要指出已有工作"做不到什么、为什么做不到"，为本研究"为什么能"铺垫
- 每个论断尽量有文献支撑；综述写法遵循 literature-review.md
- 参考文献格式遵循 citation-gbt7714.md；禁止编造文献

## 4. 撰写线：研究内容、目标与关键科学问题

**研究内容**（3-4 条为宜）：
- 每条一个相对独立又递进的模块，句式"研究内容X：XXX的XXX机制/方法研究"
- 内容量与资助强度匹配（青年 3 条左右，面上 3-4 条），贪多必被批"不聚焦"
- 内容之间逻辑：基础机理 → 方法构建 → 验证应用，层层递进

**研究目标**（1 段或 3 条内）：
- 与研究内容一一呼应，可检验、可实现（5 年内）
- 句式"揭示…机制/建立…方法/研制…系统/形成…理论"，避免"达到国际领先"类空话

**拟解决的关键科学问题**（1-2 个，最多 3 个）：
- 是"科学层面"的问题：为什么/机制是什么/规律如何
- 每个问题 + 一句话说明为什么关键（不解决则项目目标无法实现）
- 反例（不合格）：如何实现 XX 系统的开发（这是技术问题）

## 5. 撰写线：研究方案及可行性分析

**结构模板**：
```
4.1 总体研究思路与技术路线
（1）总体思路：一段话 + 一张技术路线图（必画，生成方法见第 9 节）
（2）技术路线图：科学问题 → 研究内容 → 方法手段 → 预期成果 的流程图，
    体现各内容间的数据/逻辑衔接
4.2 具体研究方案
按研究内容逐条展开：采用什么数据/材料 → 什么方法步骤 → 输出什么 → 衔接下一条
（关键步骤给参数、判据，体现"想清楚了"）
4.3 可行性分析
（1）理论可行：思路有文献/理论依据
（2）技术可行：关键方法有已发表先例或前期验证
（3）条件可行：已有设备、数据、合作基础
4.4 风险分析与应对（加分项）：Plan B 设计
```

**要点**：
- 方案颗粒度：让同行评审判断"此人已经想清楚怎么做"，而非复述教科书方法
- 技术路线图是评审重点，单独一页、要素完整、逻辑闭环

## 6. 撰写线：特色创新与研究基础

**特色与创新之处**：
- 2-3 条，分类陈述：理论创新（新机理/新模型）/ 方法创新（新方法/新范式）/ 应用创新（新场景/新数据）
- 每条结构："区别于已有…（对比对象），本项目首次/通过…（做法），实现…（突破点）"
- 忌自我拔高（"国际首次"须确有依据）、忌把研究内容换个说法当创新

**研究基础与工作条件**：
- 前期基础：与本项目直接相关的已发表论文、预实验数据、已建立的方法体系（列证据，可放代表性图表）
- 工作条件：实验室平台、设备、数据资源、团队构成（按申报书实际栏目填写）
- 青年项目另注意：个人简介突出独立性，说明与博士课题的关系（延续中深化，非简单重复）
- 只陈述真实成果，由用户提供材料，不代拟虚构

## 7. 体检线：毙稿风险体检工作流

**触发场景**：用户发来已写好的申报书草稿（全文或分章），要求"把关 / 体检 / 看看有什么问题 / 帮忙审一下"。

**体检执行六步**（按序逐项检查，全部证据取自草稿原文）：

**7.1 主线一致性体检**（核心项）
- 从草稿中提取六个关键点制成对照表：**题目 → 摘要 → 立项依据结论 → 研究内容 → 研究目标 → 预期成果**
- 逐点检查是否"一条线"：科学问题是否贯穿始终、题目与内容是否匹配、摘要 400 字是否与正文主线一致
- 任何两点之间的概念漂移（如题目说"机制"、内容做的是"系统开发"）标记为高风险

**7.2 内容-目标呼应检查**
- 制作"研究内容 ↔ 研究目标"双向对照表：每条内容是否有对应的可检验目标、每个目标是否有内容支撑
- 单向悬空（有内容无目标、有目标无内容）均标记；研究内容超过 4 条提示"不聚焦"风险

**7.3 创新点真实性体检**
- 将"特色与创新之处"逐条与"研究内容"比对：是否存在仅换措辞的伪创新
- 每条创新点检查三要素：对比对象（区别于已有…）、做法（通过…）、突破点（实现…）；缺一标记
- "国际首次/国际领先"类表述无依据时标记高风险

**7.4 关键科学问题体检**
- 逐条判断是否"科学层面"问题（为什么/机制是什么/规律如何）
- "如何开发/如何实现/如何构建 XX 系统"类技术问题 → 标记不合格并给出改写方向

**7.5 参考文献体检**
- 数量是否在 30-60 条区间
- 真伪核验 + 年份结构分析 → 按第 8 节调用 `citation_verifier.py` 执行
- 立项依据中每个关键论断是否有文献支撑（抽查关键论断）

**7.6 毙稿九条自查清单**（逐条核对，源自历年评审反馈）
- [ ] 科学问题不凝练或其实是技术/工程问题
- [ ] 研究内容过多、彼此缺乏内在逻辑
- [ ] 创新点空泛，无对比依据
- [ ] 技术路线与研究内容脱节（有内容无对应方法）
- [ ] 立项依据综述罗列文献、无批判性评述、无研究缺口论证
- [ ] 研究基础与项目方向不相关
- [ ] 关键方法交代含糊，被疑"没想清楚"
- [ ] 参考文献陈旧（近 5 年占比低）或有编造嫌疑
- [ ] 摘要（400 字中英文）与正文主线不一致

**体检报告输出格式**（每项必须包含四要素）：
```
### [风险等级：高/中/低] 问题标题
- 问题定位：第 X 节 / 第 X 段（引用原文关键句）
- 依据：对应毙稿原因/评审要点（如"创新点无对比依据"）
- 修改建议：具体可操作的改法（含示例句式）
```
报告末尾给出风险统计（高/中/低各几项）与优先修改顺序。**体检只输出风险与建议，不替用户修改申报书内容，判断权归作者**。

## 8. 体检线：参考文献体检（真伪核验 + 年份结构）

申报书参考文献 30-60 条，逐条人工核对真伪与年份结构极为耗时，且"参考文献陈旧或有编造嫌疑"是明文毙稿原因。调用本技能工具一键体检：

```bash
# 一体化：真伪核验 + 元数据补全 + 年份结构报告（联网）
python tools/citation_verifier.py 申报书文献.txt --verify --enrich

# 仅年份结构分析（不联网，秒出）：近5年占比 / 总数评估 / 缺年份清单
python tools/citation_verifier.py 申报书文献.txt --year-report
```

**体检产出**：
1. **真伪核验报告**：逐条"已验证/高置信匹配/存疑待复核/无法核验"+ 证据链接（Crossref 权威源；未命中≠编造，存疑条目须人工复核）
2. **补全后文献表**：缺失的 DOI/卷期/页码自动补齐（GB/T 7714 格式）
3. **年份结构报告**：总条数 vs 30-60 建议、**近 5 年占比**（申报书要求过半）、年份分布、缺年份条目清单、最陈旧的 5 条提示

**使用建议**：先把文献表粘贴到 txt（每行一条）跑 `--verify --enrich`，把"存疑待复核"清零后再定稿；定稿前跑一次 `--year-report` 确认年份结构达标。

## 9. 体检线：技术路线图生成与诊断

**生成**：技术路线图是评审重点，用绘图能力生成（`tools/plot_templates.py` 或智能体绘图），要素：科学问题 → 研究内容（分块）→ 方法手段 → 预期成果，用流程图形式体现各内容间的数据/逻辑衔接。

**诊断四查**（用户发来已有技术路线图时）：
- [ ] **单独成页**：评审 3-5 分钟浏览，路线图必须一页看清
- [ ] **要素完整**：科学问题、研究内容、方法、成果四层齐全，缺层即标记
- [ ] **逻辑闭环**：从问题到成果的箭头链完整，无悬空模块、无断头路
- [ ] **衔接明确**：研究内容之间的数据流转/逻辑递进关系有明确标注（而非简单并列）

诊断输出与第 7 节体检报告同格式。

## 10. 全流程工作流与交付

1. **信息收集**（必需）：用户的研究方向、目标学部/学科代码、项目类型（面上/青年/地区）、前期成果清单、可用的数据与条件。缺项先询问。
2. **提纲确认**：先输出全文提纲 + 技术路线草图文字稿，经用户确认再展开。
3. **分章撰写**（撰写线）：按第 2–6 节模板逐章撰写，每章完成后交用户核对事实性内容。
4. **三件体检**（体检线）：全文完成后依次执行——第 7 节毙稿风险体检 → 第 8 节参考文献体检 → 第 9 节技术路线图诊断。
5. **修改复核**：体检报告交用户，修改后可二次体检（主线一致性优先复检）。
6. **交付**：`.docx` 格式（可用 docx skill），技术路线图单独交付图片文件；体检报告作为附件一并交付（`体检报告.md`）。

**其他类型申报书**：省部级项目、社科基金等结构相近（立项依据/研究内容/方案/基础），撰写方法论与体检工作流均通用；具体栏目按对应申报书模板调整。

**演示样例**：`samples/demo_proposal_draft.md`（虚构标注，内置典型问题），用于体检工作流的功能验证与演示，不得当作真实申报书模板套用。
