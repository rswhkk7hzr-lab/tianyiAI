## 0. 领域内落点（微调实验结论稳健性课题）

微调实验论文的自审，在八维 rubric 之上加"稳健性专项"：①seed 数与显著性检验是否齐备（单 seed 结论=重大缺陷）；②"显著优于/SOTA"等断言是否有配对统计证据（`robustness_check` 判定等级）；③消融是否一次一因子且与主结果同 seed 集；④训练过程证据（train_doctor 诊断）是否如实报告异常 run；⑤结论边界是否写明（结论对 seed 的敏感度）。审稿视角：这五条正是实验类论文最常见的拒稿点。

| 场景 | 用户身份 | 输出 |

| 投稿前自审（模拟审稿人） | 作者 | 分维度评分表 + 按优先级的修改清单 |

审稿是学术判断行为：本模块提供结构化工具与检查弹药，**结论性判断（接收/拒稿、创新性定性）必须由用户本人作出**，AI 输出仅为参考。

## 2. 投稿前自审 rubric（八维度）

每维度 1-5 分（5 优秀 / 4 良好 / 3 合格 / 2 不足 / 1 严重缺陷）：

| 维度 | 检查要点（评分锚点） | 满分锚点（5 分） |
|---|---|---|
| 创新性 Novelty | 问题是否新、相对已有工作的增量是否明确 | 增量贡献清晰可陈述，与最近文献明确对比 |
| 方法学 Methodology | 设计是否回答研究问题；样本/数据/分析是否匹配 | 设计与研究问题精确匹配，关键步骤有参数与判据 |
| 结果可靠性 Results | 数据是否支撑结论；统计报告是否完整（统计量+自由度+p） | 每个结论可溯源到具体结果，无过度概括 |
| 逻辑结构 Logic | 引言问题→方法→结果→结论闭环；段落主题句 | 全文一条主线，无游离段落 |
| 图表质量 Figures/Tables | 编号连续、有交叉引用、可独立读懂、分辨率达标 | 读者不看正文即可理解图表 |
| 文献引用 References | 近 5 年占比、关键文献覆盖、无编造、无曲解引用 | 引用与论断匹配，按 citation-gbt7714.md 核验通过 |
| 语言表达 Language | 术语一致、无口语化、无绝对化表述 | 达投稿语言标准 |
| 伦理合规 Ethics | 数据来源合法、利益冲突声明、（涉人/动物）伦理审批号 | 声明齐全 |

**总分与处置建议**：

| 总分（40 满分） | 判定 | 建议 |
|---|---|---|
| ≥34 | 优先投稿 | 补齐 minor 问题后投稿 |
| 28-33 | 小修后投稿 | 按 ≥4 分维度清单逐项修 |
| 20-27 | 大修 | 先解决 ≤2 分维度，再重评 |
| <20 | 暂缓投稿 | 通常方法学或创新性存在结构性问题，考虑重构 |

打分必须逐维度给 1 句依据，不允许只给分数。分学科调整锚点（如方法学综述 vs 实证论文权重不同），先问用户论文类型。

## 4. 审稿意见撰写规范（审稿人场景）

结构（Summary → Major → Minor）：

```
Summary（3-5 句）：论文做了什么、主要贡献与主要问题——证明审稿人读完全文
Major Comments（编号列表）：影响结论可靠性的问题，逐条附：
  - 位置（页/行/图表号）
  - 问题陈述
  - 为什么是问题（依据：文献/方法学/数据）
  - 建议的修改方向
Minor Comments（编号列表）：语言、格式、图表细节，同样给位置
Recommendation：accept / minor revision / major revision / reject（由审稿人本人判断）
```

撰写纪律：
- 每条批评给出可执行的修改方向，不做纯否定（"写得差"→"第 3 节方法步骤缺参数，建议补充 X"）
- 区分"事实错误"与"个人偏好"：前者必提，后者标注为建议
- 语气专业克制；不评价作者本人，只评价工作
- 保密：未发表的稿件内容不得外传、不得用于自己的研究（写入交付提醒）
- 引用文献支撑批评时，同样遵守 citation-gbt7714.md 核验红线
- 利益冲突：用户存在利害关系（同方向竞争者）时提醒回避申报
