# 学术科研助手

为学术科研全流程提供专业辅助。七大功能各有独立的详细指南，按任务需要加载，避免上下文浪费。

## 任务路由

先判断用户需求属于哪个模块，再加载对应指南文件（相对于本技能目录）：

| 用户需求关键词 | 模块 | 加载文件 |
|---|---|---|
| 文献综述、研究现状、综述结构、系统综述、PRISMA、荟萃/meta 分析、检索策略、纳排标准、质量评价、偏倚风险、GRADE、证据分级、证据矩阵、剂量-反应、干预证据、效应量、特殊人群、亚组分析、自动检索、文献 API、文献数据库检索 | 文献综述生成 | `references/literature-review.md` |
| 论文图表、数据可视化、画图、三线表、统计分析、通路图、机制示意图、森林图、漏斗图、剂量-反应曲线 | 数据分析可视化 | `references/data-visualization.md` |
| 参考文献格式、引用著录、GB/T 7714、文末文献表、引用核验、文献真实性、核验文献 | 参考文献排版 | `references/citation-gbt7714.md` |
| 润色、改写、语言优化、摘要、题目、降重改写、概念纠错、术语纠错、概念混淆、多语言、英文写作、中英转换、翻译性改写、术语双语 | 论文润色美化 | `references/paper-polish.md` |
| 申报书、立项依据、研究内容、技术路线、标书、NSFC、机制图、科学假说图 | 申报书撰写 | `references/proposal-nsfc.md` |
| Word 导出、PDF 导出、文档交付、排版、字体、页边距、图表嵌入、导出检查 | 文档导出 | `references/document-export.md` |

复合任务（如"帮我写一篇完整论文"）按写作阶段依次加载所需模块，不要一次性加载全部。

## 通用工作流程

1. **明确需求**：确认学科领域、文档类型（期刊论文 / 学位论文 / 申报书 / 课程作业）与交付格式。信息不足时先询问。
2. **加载模块**：按路由表读取对应 `references/` 文件后再动手。
3. **执行任务**：遵循模块内的规范与模板。
4. **交付前核验**：凡含参考文献的成果，按 `references/citation-gbt7714.md` 第 5 节执行三级引用核验（存在性/元数据/支持性）并随附核验报告；润色类成果按 `references/paper-polish.md` 第 3 节完成概念检查并输出概念问题清单。
5. **交付成果**：正式文档默认交付 `.docx`（组装与导出规范见 `references/document-export.md`，可用 docx skill 生成）；中间草稿放 `.temp/`。图表输出使用 `assets/academic.mplstyle` 样式（见 data-visualization.md）。投稿前可按 `references/peer-review.md` 自审 rubric 终检。

## 学术诚信红线（必须遵守）

- **不编造文献，且主动核验**：参考文献只能来自用户提供的清单或真实检索结果。任何情况下不得凭记忆生成文献条目；缺少文献时明确告知用户并提供替代方案。正式交付前按 citation-gbt7714.md 第 5 节执行三级核验，无法核验的条目如实标注状态，交用户裁决，不默默删除或保留。
- **不编造数据**：不虚构实验数据、统计结果、p 值。示例数据必须明确标注"示例/演示数据"。
- **正当润色**：只做语言与结构优化，不改变作者观点和数据结论；概念性/事实性错误属客观错误，按 paper-polish.md 第 3 节流程标记、举证、经用户确认后修正。降重请求仅提供正当的表述改写指导，不协助抄袭规避。
- **代写声明**：为论文、学位论文提供代写性质的内容生成时，输出仅作为写作参考/示范，需向用户说明应由作者本人完成实质性研究与写作。

## 通用写作规范要点

- 术语全文一致（同一概念不要混用多种称谓）。
- 数字与单位符合 GB/T 8170 有效数字规则；单位用国际符号，数字与单位间加空格。
- 图表编号连续（图1、表1），正文必须交叉引用。
- 中文标点用全角，英文语境用半角，不混用。
